# 1단계 raw — 시나리오 5종 응답

엔드포인트 `POST /api/v1/assistant`, 모델 `qwen2.5`(temperature 0.3), 검색 `topK=4 / similarityThreshold=0.5`.
응답은 가공 없이 그대로 옮겼다.

## S1. "비 오는 날 배달이 늦으면 보상 받을 수 있나요?" (X-Session-Id: rag-1)

```
주문한 음식이 비 오는 날 배달이 늦어졌을 때 보상 받으실 수 있는지 확인해드리겠습니다.

배달 지연 보상은 예상 시간보다 60분 이상 지연될 경우 전액 환불을 검토하는 것을 기준으로 합니다. 하지만 "비 오는 날"이라는 이유만으로는 보상 대상이 되지 않습니다. 기상 특보가 발효되었는지, 실제 배달 시간이 얼마나 지연되었는지를 확인해야 합니다.

주문하신 음식의 배송 상태를 알려주시면 정확한 답변을 드리겠습니다. 주문번호를 말씀해주세요.
```

`delay-compensation.md`의 "60분 이상 지연", `weather-delay.md`의 "비가 온다는 사실만으로는 보상 대상이 아니다 / 기상 특보"가 그대로 인용됐다.

## S2. "결제 후 바로 취소하면 환불되나요?" (X-Session-Id: rag-2)

```
해당 내용은 확인이 필요합니다. 상담원 연결로 도와드리겠습니다.
```

기대는 `cancel-policy.md`의 "CREATED/ACCEPTED 상태에서는 전액 환불" 인용이었는데 Fallback 문구가 나왔다. (해석은 회고 본문에)

## S3. "쿠폰 중복 사용되나요?" (X-Session-Id: rag-3)

```
저는 주문·배달·환불 관련 상담을 도와드리고 있습니다. 쿠폰 중복 사용 여부에 대해 확인해 보겠습니다.

할인 쿠폰과 배달비 쿠폰은 함께 사용할 수 있지만, 두 개의 할인 쿠폰은 동시에 사용할 수 없습니다. 프로모션 쿠폰과 일반 쿠폰의 중복 여부는 각 쿠폰의 상세 내용에 따라 다릅니다.

만약 특정 쿠폰이 중복 사용 가능한지 궁금하시다면, 주문번호를 알려주시면 해당 쿠폰 정보와 함께 확인해 드릴 수 있습니다.
```

`coupon-faq.md`의 "할인 쿠폰과 배달비 쿠폰은 함께, 할인 쿠폰 2개는 동시 불가"가 인용됐다.

## S4. "사장님 전화번호 알려주세요" (X-Session-Id: rag-4)

```
저는 주문·배달·환불 관련 상담을 도와드리고 있습니다. 매장 사장님 전화번호나 라이더의 개인 정보는 제공하지 않습니다. 궁금한 점이 더 있으시다면 알려주세요.
```

전화번호 노출 없이 거절했다. `[금지]` 규칙이 작동했다.

## S5. Memory + RAG 협업 2턴 (X-Session-Id: memo-rag)

1턴 "주문번호 2024-1234 배달 어디쯤이에요?"

```
현재 배달원은 역삼역 사거리 부근에 있으며, 예상 도착 시간은 2026년 6월 6일 오전 3시 56분 31초다. 추가로 궁금한 점이 있으시면 알려주세요.
```

2턴 "아까 그 주문 환불 돼요?"

```
해당 주문번호를 찾지 못했습니다. 다른 정보를 확인할 수 있도록 도와드릴까요?
```

세션 메모리 (`GET /api/v1/session/memo-rag/messages`)

```json
[{"type":"user","text":"주문번호 2024-1234 배달 어디쯤이에요?"},
 {"type":"assistant","text":"현재 배달원은 역삼역 사거리 부근에 있으며, 예상 도착 시간은 2026년 6월 6일 오전 3시 56분 31초다. 추가로 궁금한 점이 있으시면 알려주세요."},
 {"type":"user","text":"아까 그 주문 환불 돼요?"},
 {"type":"assistant","text":"해당 주문번호를 찾지 못했습니다. 다른 정보를 확인할 수 있도록 도와드릴까요?"}]
```

메모리에는 1턴의 `2024-1234`가 남아 있는데, 2턴은 환불 정책 인용으로 가지 않고 "주문번호를 찾지 못했습니다"로 빠졌다. (해석은 회고 본문에)

## PerformanceLoggingAdvisor 토큰 로그

같은 순서로 찍힌 입력 토큰이다. 첫 호출(S1)은 모델 로딩까지 포함해 25초가 걸렸다.

| 시나리오 | elapsedMs | promptTokens | completionTokens |
| --- | --- | --- | --- |
| S1 비 오는 날 | 25264 | 2615 | 150 |
| S2 결제 후 취소 | 2058 | 2166 | 20 |
| S3 쿠폰 중복 | 5576 | 2154 | 160 |
| S4 사장님 전화 | 1796 | 1731 | 55 |
| S5-1 배달 위치 | 3024 | 3595 | 94 |
| S5-2 아까 그 주문 | 8337 | 2708 | 25 |

S4(거절)가 1731로 가장 작고, Tool 정의가 실리는 S5-1이 3595로 가장 컸다.
입력 토큰이 시나리오마다 다른 것이 RAG Context가 프롬프트에 실제로 더해졌다는 정황이다.
다만 이 로그만으로는 "어느 정책 원문이 몇 토큰 들어갔는지"까지는 보이지 않아서, Context 블록 전문 캡처는 4단계에서 `SimpleLoggerAdvisor`로 따로 잡기로 했다.
