# 4단계 raw — RAG 주입의 토큰 비용 (3조건)

질문 고정: "배달 완료 후에도 환불 받을 수 있나요?" (첫 턴, 빈 메모리)
조건별로 AssistantController의 defaultAdvisors만 바꿔 재기동 후 측정.

| 조건 | Advisor 체인 | promptTokens | completionTokens | 응답 |
| --- | --- | --- | --- | --- |
| (a) Memory·RAG 없음 | performance | 1688 | 20 | Fallback |
| (b) Memory만 | memory, performance | 1688 | 20 | Fallback |
| (c) Memory + RAG | memory, rag, performance | 2590 | 20 | Fallback |

- (c) − (a) = **902 토큰**. 이게 RAG가 주입한 Context(정책 원문) 분량이다.
- (a) = (b) = 1688: 첫 턴이라 메모리가 비어 있어 Memory advisor가 토큰을 더하지 않았다.
- 셋 다 응답이 Fallback이다. (a)(b)는 RAG가 없어 정책을 못 찾으니 당연하고, (c)는 Context가 902 토큰 실렸는데도 LLM이 그걸 근거로 쓰지 못하고 Fallback으로 빠졌다. "토큰을 더 쓰면 정확도가 오른다"가 이 케이스에서는 성립하지 않았다.

## 로그 발췌

```
(a) LLM call elapsedMs=10120 promptTokens=1688 completionTokens=20 totalTokens=1708
(b) LLM call elapsedMs=9517  promptTokens=1688 completionTokens=20 totalTokens=1708
(c) LLM call elapsedMs=13358 promptTokens=2590 completionTokens=20 totalTokens=2610
```

## (c)에서 RAG가 주입한 Context 블록 전문

기본 로깅으로는 프롬프트가 안 찍혀, 3단계에서 order(5)로 RAG를 먼저 돌렸을 때 ChatMemory에 그대로 저장된 증강 프롬프트로 Context 전문을 확보했다(`단계3-뒤바꿈-order5.md`). RAG는 이런 형태로 정책 원문을 프롬프트에 끼운다.

```
Context information is below, surrounded by ---------------------
---------------------
# 환불 기본 정책
- 조리 시작 전 취소: CREATED/ACCEPTED인 경우 전액 즉시 취소/환불
- 음식 누락/오배송: 배달 완료 후에도 증빙 조건으로 전액/부분 환불
- 배달 지연 과도(60분 이상): 배달비 환불 또는 쿠폰 보상
- 배달 완료 후 24시간 초과: 단순 맛 불만족은 환불 대상 아님
...
# 주문 취소 정책
- CREATED / ACCEPTED: 자동 취소 가능, 전액 환불
- COOKING / DELIVERING / DELIVERED: 자동 취소 불가 ...
---------------------
Given the context and provided history information and not prior knowledge,
reply to the user comment. If the answer is not in the context, inform
the user that you can't answer the question.
```
