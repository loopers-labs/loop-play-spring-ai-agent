# Round 4 회고 — 배운 것 / 의문점 / 다음에 시도할 것

## 내가 배운 것

이번 라운드에서 머리에 가장 오래 남은 건 RAG를 켜는 일이 아니라, RAG가 다른 Advisor와 섞일 때 생기는 부작용이었습니다.

청킹은 문서 길이에 완전히 종속된다는 걸 실측으로 체감했어요.
교재는 큰 청크에서 row가 줄고 유사도가 뭉툭해진다고 했는데, 우리 정책 문서는 800이든 2000이든 똑같이 1청크로 들어가서 C 실험이 아무 변화를 못 만들었습니다.
반대로 100으로 줄였더니 7건이 49조각으로 흩어지면서 "60분", "+30분" 같은 숫자가 다른 청크로 갈려 답이 뭉개졌고요.
그래서 "이 도메인의 최적 청크는 800"이라는 결론보다, "조항형 짧은 문서에서는 잘게 써는 것만 손해고 키우는 건 의미 없다"는 감각이 남았습니다.

가장 강렬했던 건 3단계 Advisor 순서였어요.
order를 5로 바꿔 RAG를 Memory보다 먼저 돌렸더니, RAG가 만든 "정책 원문이 박힌 증강 프롬프트"가 그대로 ChatMemory에 사용자 발화로 저장됐습니다.
일회성이어야 할 Context가 영구 기록으로 굳어 버린 거라, "왜 Memory가 먼저인가"를 글이 아니라 오염된 메모리 JSON으로 봤습니다.

Fallback은 두 겹이어야 한다는 것도 직접 떼어 보고 알았어요.
`[정책 인용 규칙]`을 빼니 도메인 밖 "오늘 점심" 질문에 모델이 메뉴를 추천하며 범위를 넘어갔고, `similarityThreshold` 하나만으로는 그걸 못 막았습니다.
검색 단계의 임계값과 생성 단계의 모름 규칙이 같이 있어야 했어요.

마지막으로 토큰. RAG는 첫 질문부터 Context만큼(이번엔 902 토큰) 바로 더 먹는데, 그 902를 내고도 응답이 Fallback인 경우가 있었습니다.
"정확도를 토큰으로 산다"는 말이 항상 성립하는 건 아니라는 걸, Context를 넣는 것과 모델이 그걸 쓰는 게 별개라는 형태로 배웠습니다.

## 의문점

- 같은 질문(비 오는 날 보상)이 1단계에서는 정책을 인용하고 2단계 재실행에서는 Fallback으로 빠졌습니다. qwen2.5의 비결정성과 0.5 임계값 경계가 겹친 걸로 보이는데, 한국어 임베딩에서 "맞는 정책은 통과하고 도메인 밖은 떨어지는" 임계값을 어떻게 정량적으로 측정해야 할지 아직 모르겠어요. 유사도 점수 분포를 직접 찍어 봐야 할 것 같습니다.
- (c) 조건에서 환불 정책이 902 토큰이나 실렸는데도 Fallback이 나왔습니다. 이게 검색이 임계값에 걸려 Context가 사실 비었던 건지, 아니면 Context는 들어갔는데 모델이 안 쓴 건지 토큰 숫자만으로는 못 가릅니다. `SimpleLoggerAdvisor`로 검색 결과와 최종 프롬프트를 같이 봐야 갈릴 문제예요.
- 검색 결과의 출처(`metadata.title`)를 응답에 자동으로 붙이려면 `QuestionAnswerAdvisor`만으로는 부족해 보이는데, `RetrievalAugmentationAdvisor`나 후처리가 필요한지 아직 안 봤습니다.
- 정책 문서가 자주 바뀌는 운영에서는 `alreadyLoaded`의 "id 있으면 스킵"이 내용 변경을 못 잡습니다. 해시 기반 재적재나 증분 인덱싱을 언제 어떻게 트리거할지가 숙제로 남았어요.

## Round 5(Guardrail)에 시도하고 싶은 것

3단계에서 본 메모리 오염과 4단계에서 본 "검색 0건인데 토큰만 쓰는" 케이스가 자연스럽게 다음 라운드로 이어집니다.

- RAG 검색 결과가 0건이거나 유사도가 너무 낮으면, 모델에게 떠넘기지 않고 바로 "상담원 연결" Tool을 호출하는 Guardrail Advisor를 끼워 보고 싶습니다. 지금은 Fallback 문구로 막지만 그건 여전히 LLM의 선의에 기대는 거라서요.
- 1단계 S4에서 본 "사장님 전화번호 알려주세요" 같은 `[금지]` 질문은 임베딩·검색 자체를 건너뛰는 입력 필터가 있으면 토큰도 아끼고 사고도 줄겠다 싶었습니다.
- order를 뒤집었을 때 본 메모리 오염도, 메모리에 개인정보가 섞이면 그대로 벡터 검색에 흘러가는 위험과 연결됩니다. 임베딩 쿼리에서 민감 정보를 빼는 필터를 Guardrail 단계에서 어떻게 둘지 고민해 보려고 합니다.
