# Temperature Sweep 실험 리포트

> 목적: temperature 0.3 선택 근거를 데이터로 정당화한다.

---

## 1. 실험 설계

### 1) 조건

| 항목 | 값 |
|------|----|
| temperature | 0.0 / 0.3 / 0.7 |
| 프롬프트 | `BaedalPrompt.SYSTEM_PROMPT` (구조화 프롬프트) |
| repeat | 10회 |
| 엔드포인트 | `POST /api/v1/prompt-lab` |


### 2) 케이스

| ID | 입력 | 선정 이유 |
|----|------|-----------|
| A. 이물질 | `"음식에 벌레가 나왔어요"` | 정답이 명확한 케이스. 고온에서도 형식을 유지하는지 확인 |
| B. 취소·환불 | `"방금 시킨 주문 취소하고 싶어요. 환불은 얼마나 걸려요?"` | 이전 실험에서 한자 혼입이 발생한 케이스. temperature 의존성 확인 |
| C. 라이더 사고 | `"라이더가 음식을 엎었다는데 보상 받을 수 있나요?"` | 예시 앵커링이 강한 케이스. 온도가 올라갈수록 다양성이 생기는지 확인 |

### 3) 평가지표 정의

| 지표 | 정의 | 목적 |
|------|------|------|
| `nextActionComplianceRate` | 허용된 nextAction 값(`주문 상태 조회 요청` / `추가 정보 확인` / `상담사 연결` / `안내 완료`)을 정확히 반환한 비율 | 형식 안정성 측정 |
| `categoryConsistency` | 10회 중 동일 category를 반환한 비율 | 분류 안정성 측정 |
| `neededInfoCompletenessRate` | 처리에 필요한 정보를 neededInfo에 빠짐없이 포함한 비율 | 정보 수집 정확도 측정 |
| 고유 응답 수 | 10회 중 summary 텍스트가 서로 다른 응답의 수 | 앵커링 강도(재현성 vs 다양성) 측정 |
| 한자 혼입 횟수 | nextAction / neededInfo에 CJK 한자가 섞인 횟수 | 언어 일관성 위반 측정 |

## 3. 평가

### 형식 안정성

`categoryConsistency`는 3개 온도, 3개 케이스 모두 1.0이었다. category 분류는 temperature의 영향을 받지 않는다.

`nextActionComplianceRate` 이탈은 취소·환불 케이스에만 집중됐다. nextAction 문자열이 길고 복잡할수록 고온에서 형식 이탈이 발생하기 쉽다.

### neededInfo 정확도

이물질·라이더 사고 케이스는 3개 온도 모두 `neededInfoCompletenessRate: 1.0`으로 안정적이었다.

취소·환불 케이스는 3개 온도 모두 `0.0`이었다. 주문번호 없이 취소를 요청했음에도 `neededInfo`가 빈 배열로 반환됐다. 이는 temperature와 무관한 **프롬프트 설계 문제**다 — 주문번호가 없으면 `neededInfo`에 반드시 포함하라는 규칙이 이 케이스에서 작동하지 않았다.

추가로 취소·환불 케이스에서 한자 혼입이 `neededInfo`에도 발생했다.

| temperature | 한자 혼입 내용 |
|:-----------:|--------------|
| 0.0 | 없음 |
| 0.3 | `['订单号']` 1회 |
| 0.7 | `['周订单号']` 1회, `['主订单号']` 1회 |

한자 혼입은 `nextAction`에서 시작해 `neededInfo`까지 번지며, temperature가 높을수록 확산된다.

### nextAction과 neededInfo의 temperature 민감도 차이 — 근본 원인

`nextAction`과 `neededInfo`가 같은 temperature 변화에서 다른 분포를 보인 이유는 **의사결정 구조의 차이**다.

```text
[nextAction] — 하나의 결정

  enum 중 1개 선택:
    "추가 정보 확인"   70%   ← 1위
    "상담사 연결"      20%
    "조회 안내"         7%
    기타                3%

  → 1위와 2위 격차가 큼 (뾰족한 분포)
  → temperature가 올라가도 1위가 거의 유지됨
```

```text
[neededInfo] — 여러 독립 결정의 묶음

  항목마다 개별 의사결정:
    "이물질 사진"을 포함할까?    포함 90% / 생략 10%
    "주문번호"를 포함할까?       포함 30% / 생략 70%
    "발생 시각"을 포함할까?      포함 20% / 생략 80%

  → 항목 N개면 2^N 조합 가능
  → temperature가 올라가면 더 많은 조합 등장
  → 빈 리스트 [], 추가 항목 등 출현
```

`nextAction`은 하나의 결정, `neededInfo`는 여러 독립 결정의 묶음이다. **결정 횟수가 많을수록 temperature 영향이 누적되어 출력이 흔들린다.**

### 재현성 vs 다양성

| temperature | 특성 |
|:-----------:|------|
| 0.0 | 형식 완벽. 그러나 3개 케이스 모두 10/10 완전 동일 응답 — 재현성 과잉 |
| 0.3 | 형식 이탈 1/30(3.3%). 고유 응답이 최대 5개로 자연스러운 변주 |
| 0.7 | 형식 이탈 5/30(16.7%). 이물질 케이스에서 규칙 위반 표현 등장 ("식중독의 위험이 있으니 즉시...") |

t0.7의 이물질 케이스에서 `"식중독의 위험이 있으니 즉시 건강에 대한 불편함을 확인해주세요"`처럼 사실 확인 전 단정하는 표현이 나타났다. 이는 프롬프트 금지 규칙 위반이다.

### 예상 패턴과 실제 비교

| temperature | 예상 | 실제 |
|:-----------:|------|------|
| 0.0 | 형식 완벽, 응답 고정 | ✅ 일치 |
| 0.3 | 형식 높음, 일부 동일 | ✅ 일치 |
| 0.7 | 형식 낮아지기 시작 | ✅ 일치 (단, 취소·환불 단독 40% 이탈로 예상보다 빠름) |

## 4. 온도별 탈락 사유

| temperature | 탈락 사유 | 채택 여부 |
|:-----------:|-----------|:---------:|
| 0.0 | 형식은 완벽하지만 10/10 완전 동일 응답. 같은 문의에 항상 동일한 문장을 반환하면 상담 품질이 경직된다. | ❌ |
| **0.3** | 형식 이탈 1/30(3.3%), category 완전 안정, 고유 응답 최대 5개. 형식 안정성과 응답 다양성의 균형점. | ✅ **채택** |
| 0.7 | 취소·환불 케이스에서 한자 혼입 4/10(40%). 이물질 케이스에서 금지 규칙 위반 표현 등장. 운영 기준 이하. | ❌ |

## 5. 결론

**temperature 0.3을 선택한 경험칙이 실험 데이터로 정당화됐다.**

- 형식 이탈률 3.3% — 허용 가능한 수준
- 재현성 과잉(t0.0) 없이 응답 다양성 확보
- 금지 규칙 위반 표현 없음 (t0.7에서는 발생)
- category 분류 완전 안정

### 한계 및 후속 과제

- 한자 혼입은 temperature 외에 프롬프트 강화("한국어로만 작성" 명시)로도 개선 가능. t0.7이 프롬프트 수정 후에도 동일한 이탈률을 보이는지 재검증 필요.
- 3개 케이스는 대표성이 제한적이다. 에스컬레이션·욕설·법적 시사 등 극단 케이스에서 동일한 패턴이 유지되는지 추가 검증 필요.
