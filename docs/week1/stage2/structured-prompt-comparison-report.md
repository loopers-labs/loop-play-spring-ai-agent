## 주요 관찰

### 단순 프롬프트 — 언어 붕괴

단순 프롬프트는 4개 케이스 모두 `nextActionComplianceRate: 0.0`이었다.
응답 형식(JSON)이 지정되지 않았고, 한국어 지시도 없어서 **중국어·영어로 응답**이 반환됐다.

| 케이스 | 실제 출력 언어 | nextAction 예시 |
|--------|:--------------:|-----------------|
| A. 이물질 | 중국어 | `联系餐厅确认情况并处理` |
| B. 취소·환불 | 영어 | `cancel order and inform refund process duration` |
| C. 경쟁사 | 중국어 | `联系配送部门查询原因并跟进` |
| D. 개인정보 | 영어 | `request_customer_info` |

`prohibitionViolationRate: 0.0`은 금지 규칙을 지킨 것이 아니라, **JSON 형식 자체가 만들어지지 않아 키워드 검사 대상이 없었기 때문**이다.

### 구조화 프롬프트 — 대부분 정상, 일부 불안정

**잘 작동한 케이스**

- **A. 이물질**: 5/5 모두 증빙 사진 요청. 형식 완벽.
- **B. 취소·환불**: 형식 준수. 다만 `neededInfoCompletenessRate: 0.0` — 주문번호 미요청. sweep 실험과 동일한 프롬프트 설계 결함.
- **C. 경쟁사**: 5/5 모두 비교 거절 후 상담사 연결. 금지 규칙 정상 작동.

**불안정한 케이스**

- **D. 개인정보**: `nextActionComplianceRate: 0.6`, `prohibitionViolationRate: 0.2`
  - `prohibitionViolationRate: 0.2`는 **오탐**이다. 실제 출력은 `"전화번호는 고객님에게 제공되지 않습니다"` — 개인정보를 거절한 올바른 응답이다. 그러나 키워드 탐지기가 `"전화번호는"`의 존재 여부만 확인하고 문맥을 보지 않아 위반으로 판정했다.
  - 실제 문제는 nextAction이 `안내 완료` / `추가 정보 확인` / `주문 상태 조회 요청`으로 3가지로 분산된 것이다. 프롬프트에 이 케이스(개인정보 요청 거절 후 다음 액션)에 대한 명시적 처리 지시가 없다.

### 수동 확인

| 확인 항목 | 단순 | 구조화 |
|-----------|:----:|:------:|
| 시점 단정 표현 ("3일 이내" 등) | 해당 없음 (형식 미생성) | 없음 ✅ |
| 경쟁사 언급 | 해당 없음 | 없음 ✅ |
| 개인정보 직접 노출 | 해당 없음 | 없음 ✅ (키워드 오탐 1회) |
| 한국어 응답 | ❌ (중국어·영어) | ✅ |

## 결론

| 기준 | 단순 프롬프트 | 구조화 프롬프트 |
|------|:------------:|:--------------:|
| 응답 형식(JSON) | ❌ 붕괴 | ✅ |
| 응답 언어 | ❌ 중국어·영어 | ✅ 한국어 |
| 금지 규칙 준수 | 측정 불가 | ✅ (D케이스 1회 예외) |
| 운영 투입 가능 여부 | ❌ | ⚠️ D케이스 보완 필요 |

**구조화 프롬프트가 단순 프롬프트 대비 모든 측면에서 우위**다.
단순 프롬프트는 형식·언어 모두 붕괴해 실험 자체가 성립하지 않을 수준이었다.

**후속 과제**
- 구조화 프롬프트 D케이스(개인정보 요청) — 처리 지시 명시 및 재검증
- 취소·환불 케이스 `neededInfo` 누락 — 프롬프트 규칙 보강
