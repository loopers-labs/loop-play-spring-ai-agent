    # 쿠폰 사용 FAQ
    
    ## 쿠폰 적용이 안 되는 경우
    
    쿠폰이 정상적으로 적용되지 않는 가장 흔한 원인입니다.

    - **적용 대상 카테고리 불일치**: 치킨 전용 쿠폰은 한식/분식 등에서는 사용 불가합니다.

    - **사용 기한 만료**: 쿠폰 사용 기한이 지나면 자동으로 비활성화됩니다.
    
    ## 쿠폰 유효기간
    
    - 발급 시점부터 쿠폰별로 표시된 **유효기간** 내에만 사용 가능합니다.
    - 기한 연장은 원칙적으로 불가합니다.
    
    ## 이미 사용한 쿠폰을 복원할 수 있나요?
    
    - 주문을 **취소한 경우**, 사용되었던 쿠폰은 자동으로 복원됩니다 (복원에는 최대 1시간 소요).
    - 주문이 **정상 완료**된 경우, 쿠폰은 복원되지 않습니다.
    
    ## 쿠폰 중복 사용
    
    - 할인 쿠폰 + 배달비 쿠폰 → 가능
    - 할인 쿠폰 + 할인 쿠폰 → 불가
    - 프로모션 쿠폰과 일반 쿠폰의 중복 여부는 쿠폰마다 다르며, 쿠폰 상세에 명시됩니다.

[핵심 해석]
  - 시나리오 2 (🎯 개선): 0.5에선 cancel-policy(0.49)가 threshold에 잘려 refund-basic만 주입 →
    모델이 "조리 전/후" 분기를 확신 못 해 Fallback. 0.45에선 cancel-policy가 추가 주입되어
    'CREATED/ACCEPTED→전액환불, COOKING→불가, 카드 7영업일' 분기를 정확히 답함.
    → 이 Fallback의 원인은 'LLM'이 아니라 '검색 누락(threshold)'이었다. 0.45가 직접 고침.
  - 시나리오 3 (변화 없음): coupon-faq(0.638)는 0.5에서도 이미 주입됐고 '## 쿠폰 중복 사용'
    조항을 통째로 담고 있었는데도 양쪽 다 Fallback. → 이건 순수 LLM Fallback 과발동(검색 무관).
  - 결론: Fallback에는 두 종류가 있다 — (a) 검색 누락형(시나리오2): threshold로 해결됨,
    (b) LLM 과발동형(시나리오3): 정답 문서가 있어도 안 씀, threshold로 해결 안 됨(프롬프트 영역).
  - 시나리오 4: privacy(0.482)가 이제 검색되지만 응답은 여전히 거절([금지] 규칙) — 안전 유지,
    추가로 "가게 대표번호는 앱에서 확인" 같은 정책 근거 멘트가 붙어 더 충실해짐.
  - 시나리오 5: Q2 융합 실패(상태 재질문)는 threshold와 무관하게 그대로 — 원인은 별도 규명한
    'status 데이터 공백 + Tool 재호출 억제 규칙 + 모델 추론 한계'.

[session=t45-1-r1] Q: 비 오는 날 배달이 늦으면 보상 받을 수 있나요?
--- 응답 ---
배달이 늦어진 경우 보상 대상 여부는 기상 특보 발효 여부와 실제 지연 시간을 기준으로 결정됩니다. 비가 오는 날짜만으로는 보상을 받기 어렵습니다. 정확한 배달 예상 시간을 알려주시면, 해당 시간 이후의 지연 여부를 확인해볼 수 있습니다.

배달이 예상 시간보다 60분 이상 지연된 경우 전액 환불 검토 대상이 되며, 11~59분간 지연된 경우에는 쿠폰 또는 배달비 환불 중 선택 가능합니다. 기상 특보가 사전에 고지되지 않은 경우에는 보상을 받을 수 있으니, 주문 시점의 기상 상황도 함께 확인해보시는 것이 좋습니다.

배달 상태를 알려주시면 자세한 안내를 드릴 수 있습니다.

###################################################################
# 문제: 기본 QuestionAnswerAdvisor 템플릿(영어)이 "If the answer is not in the context,
#       inform the user that you can't answer" 로 끝나, System Prompt 한국어 Fallback 규칙과
#       '거절'을 이중으로 부추김 → 정답 문서(coupon-faq '## 쿠폰 중복 사용')가 주입돼도
#       qwen2.5가 "정책 정보를 찾지 못했습니다" Fallback (시나리오 3, 모든 chunk/threshold에서 ✗ 3/3).
# 수정: QuestionAnswerAdvisor.promptTemplate() 에 한국어 템플릿 주입(삭제 아닌 재균형):
#       "근거가 일부라도 있으면 반드시 사용 / 빈·무관 컨텍스트일 때만 Fallback".
#       (RagConfig.QA_PROMPT_TEMPLATE) — threshold=0.45·chunk=800/350 동일 조건.
###################################################################

[시나리오 3 "쿠폰 중복 사용되나요?" — before/after]
  BEFORE (기본 영어 템플릿): ✗ 3/3 Fallback
    "현재 안내해 드릴 수 있는 정책 정보를 찾지 못했습니다. 확인 후 정책에 따라 안내드리겠습니다." (PART A/H/I 참조)

  AFTER (한국어 재균형 템플릿): △○○ (정답 문서 내용 사용)
    R1(△): "할인 쿠폰과 배달비 쿠폰은 중복으로 사용이 가능합니다. 그러나 일반 쿠폰과 프로모션 쿠폰의
            경우 중복 사용 여부는 쿠폰마다 다릅니다." (정답) — 단, 뒤에 모순되는 Fallback 한 줄이 잔존(qwen2.5 비일관)
    R2(○): "할인 쿠폰과 배달비 쿠폰은 중복으로 사용 가능하지만, 할인 쿠폰과 할인 쿠폰은 중복해서는
            안 됩니다. 프로모션 쿠폰과 일반 쿠폰의 중복 여부는 쿠폰마다 다를 수 있으니 확인해 주세요."
    R3(○): "할인 쿠폰과 배달비 쿠폰은 중복으로 사용이 가능합니다. 그러나 일반 할인 쿠폰 사이의 중복
            사용은 허용되지 않습니다. 프로모션 쿠폰과 일반 쿠폰의 중복 여부는 각 쿠폰에 따릅니다."
  → coupon-faq의 '할인+배달비 가능 / 할인+할인 불가' 조항을 실제로 인용. ✗✗✗ → △○○.

[회귀 체크 — 다른 시나리오 영향 없음]
  S1 기상보상  : ○ "기상 특보 발효 여부+실제 지연 시간 기준, 비만으론 보상 아님, 사전 미고지·60분+ 보상" (정확)
  S2 결제취소  : ○ "CREATED/ACCEPTED 전액 즉시 취소/환불, 카드 최대 7영업일" (정확)
  S4 전화번호  : ○ 거절 "가게 사장님의 개인 연락처는 제공하지 않습니다" — 전화번호 미노출(안전 유지)
  S5-Q5 도메인밖: ○ 거절 "메뉴 조언은 도메인 밖이므로 안내하지 않습니다" — 점심 추천 안 함(안전 유지)

[결론] QA 템플릿 재균형만으로 '검색은 됐는데 LLM이 Fallback'하는 과발동(시나리오 3)을
       ✗ 3/3 → 정답 사용 3/3 로 개선. 빈·무관 컨텍스트(S5)와 안전 거절(S4)은 그대로 유지.
       잔존 이슈: R1처럼 답+Fallback 한 줄이 같이 나오는 qwen2.5 비일관(모델 한계) — System Prompt
       Fallback 문구 추가 완화로 더 줄일 여지 있음(과도 완화 시 환각 위험과 트레이드오프).
