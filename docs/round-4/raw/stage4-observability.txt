[정량 비교 — PerformanceLoggingAdvisor 로그 발췌]
  조건                         체인                                  입력토큰  출력토큰  총토큰
  ----------------------------------------------------------------------------------------------
  (a) Memory✗ RAG✗   --chain.memory=false --chain.rag=false  perf만            3211     52     3263
  (b) Memory만(빈)    --chain.memory=true  --chain.rag=false  memory+perf       3211     59     3270
  (c) Memory + RAG    (기본)                                  memory+rag+perf   4096    316     4412

  · (b)=(a)=3211 입력 → 빈 Memory(첫 턴)는 토큰을 0 추가. "Memory 자체는 공짜, RAG가 비용을 먹는다".
  · (c) 4096 − (a) 3211 = +885 토큰 (+27.6%) = RAG Context(정책 원문) 주입 비용.
    (4096은 num_ctx 경계 가능성 — 주입 원문이 더 길면 절단됐을 수 있음.)
  · 출력도 (c) 316 vs (a) 52 — RAG 있으면 정책 원문을 인용해 답이 충실/길어짐.

  # 배달 완료 후 환불 정책
  배달이 완료된 상태에서도 아래 사유에 한해 환불을 요청할 수 있습니다.
  ## 배달 완료 후 환불 가능 사유
  1. **메뉴 누락**: 주문한 메뉴 중 일부가 도착하지 않은 경우.
  2. **오배송**: 주문한 메뉴가 아닌 다른 메뉴가 도착한 경우.
  3. **품질 불량**: 음식에 이물질이 포함되었거나, 상한 음식이 도착한 경우.
  4. **수량 오류**: 주문 수량보다 적게 도착한 경우.
  ## 접수 시한
  - 배달 완료 후 **24시간 이내** 접수만 유효합니다.
  - 24시간을 초과하면 단순 맛 불만족과 함께 환불 대상에서 제외됩니다.
  ## 필수 증빙
  - 누락/오배송: 받은 음식의 사진 (포장 상태 포함)
  - 품질 불량: 이물질 또는 변질 상태가 보이는 사진
  ## 처리 흐름
  1. 앱 내 "1:1 문의"에서 주문번호를 선택합니다. 2. 사유 + 사진을 제출합니다.
  3. 정책 범위 내 건은 상담사 확인 후 당일 처리됩니다. 4. 이견 시 최대 3영업일 내 중재.
  ## 부분 환불
  - 누락/오배송된 **해당 메뉴만 부분 환불**이 기본 원칙입니다.
  - 전체 주문에 영향을 준 품질 문제(이물질 등)는 전액 환불로 처리될 수 있습니다.
  # 환불 기본 정책
  배달에서 주문 환불은 **주문 상태**와 **사유**에 따라 다르게 처리됩니다.

[결론]
  - RAG의 토큰 비용은 'Context에 삽입된 정책 원문'의 크기다((c) +885토큰). Memory(빈)는 0.
  - 그 비용의 대가로 답이 '일반론(a)'에서 '정책 원문 인용(c)'으로 바뀐다 — 비용 ↔ 정확성 트레이드오프.
  - 운영 함의: topK·문서 길이가 곧 입력 토큰·비용. 짧은 정책 문서 + topK 4 + threshold 0.45가
    "필요한 1~2개 정책만 주입"으로 비용을 억제하는 이유(설계 결정 2·4와 연결).
