# 1주차 - 블로킹

> `SupportController`에 `.call()` 한 줄 박아두고, 한참 그 한 줄만 들여다봤어요.

## 처음엔 그냥 외부 호출인 줄 알았어요

`.call()` 라인이 평소 짜던 외부 API 호출이랑 모양이 똑같아서, 처음엔 별 생각 없이 넘겼습니다.
근데 직접 한 번 호출해보니까 응답이 돌아오는 데 5초쯤 걸리더라고요.

평소 다루던 외부 호출은 길어도 수백 ms 안에 끊겼어서, 단위가 한 자릿수 다르다는 게 자꾸 걸렸어요.
같은 동기 호출이라도 100ms 짜리랑 5초짜리는 다루는 방식이 달라야 할 것 같은데, 그게 정확히 어떻게 달라야 하는지는 한 번에 안 잡혔습니다.

## 스레드 풀 얘기는 좀 조심해서 봐야 할 것 같습니다

블로킹 이슈 얘기 나오면 다들 "스레드 풀이 마른다" 부터 꺼내는데, 이 얘긴 일단 조심해서 보려고 합니다.
머리로 계산하면 그럴듯하긴 해요 — Tomcat 기본 max 스레드가 200이라 치고, 5초짜리 호출이 동시에 200건 들어오면 풀이 통째로 잡히는 거 아니냐.

근데 진짜 그 그림이 나오는지는 액추에이터 메트릭 띄워두고 직접 부하를 줘봐야 알 것 같아요.
Tomcat은 acceptor 큐도 있고, 환경마다 풀 사이즈도 다 다르고, 실제 트래픽이 200건 동시 폭주랑은 거리가 있을 수도 있으니까요.
이 부분은 "이론상 위험하다" 까지만 적어두고, 숫자는 직접 본 다음에 다시 정리하려고 합니다.

## .stream() 보면서 한 번 잘못 들어갔던 부분

`StreamingChatController` TODO에 `.stream()` 쓰고 `Flux<String>` 반환하라고 적혀 있어서, 이걸 처음 보고는 "WebFlux로 컨트롤러를 갈아엎어야 되나" 생각했어요.
`Flux` 반환 = Reactive 스택 = 서블릿 버리고 Netty로 가는 거다, 이런 식으로 잠깐 잘못 묶었습니다.

찾아보니까 그건 제 착각이었어요.
Spring MVC (서블릿) 위에서도 컨트롤러가 `Flux<String>`을 그대로 반환할 수 있고, MVC 내부에 `ReactiveTypeHandler` 가 끼어서 알아서 처리해줍니다.
서블릿 3.0 async 처리 위에서 토큰을 SSE로 흘려보내는 식이라, "WebFlux로 갈아엎는다" 가 아니라 "응답을 점진적으로 흘려보내는 모드 하나 더 쓴다" 에 가까웠어요.

이걸 헷갈렸던 게 좀 부끄러운데, `Flux` 라는 타입만 보면 자동으로 WebFlux 떠올리는 버릇이 있었던 것 같습니다.

## 그래서 진짜 바뀌는 건 뭔가

스레드 측면에서 `.call()` 과 `.stream()` 이 얼마나 다른지는 솔직히 아직 감이 안 와요.
둘 다 결국 HTTP 호출 하나 들고 응답을 기다리는 건 비슷한데, 응답을 통째로 받느냐 토큰 단위로 받느냐의 차이라.
async 처리로 들어가면 요청 받는 스레드는 일찍 풀려나니까 풀 압박이 좀 덜할 수는 있을 것 같은데, 이건 진짜 측정해봐야 할 영역이에요.

오히려 차이가 분명해 보이는 쪽은 사용자 체감입니다.
ChatGPT 화면이 글자 한 자씩 떨어지는 거 매일 보면서도 정작 "저게 왜 저렇게 보이도록 만들어진 건가" 는 깊게 생각해본 적이 없었는데, 다시 보니까 그게 단순한 UI 효과가 아니라 백엔드가 토큰 단위로 흘려보내고 있는 신호였더라고요.
첫 토큰까지 걸리는 시간 (TTFT 라고 부르더라고요) 만 짧으면, 전체 응답 시간이 같아도 사용자가 받는 느낌이 다르다는 얘기.

이것도 단정하긴 좀 그렇고, `curl -N` 으로 한 번 받아보고 손으로 비교해본 다음에 다시 정리해야 할 것 같아요.

## 안 풀린 채로 두는 것들

`.call()` 을 무조건 못 쓴다는 결론으로 가긴 싫었어요.
`SupportController` 처럼 분류된 JSON 한 덩어리 받는 케이스는, 부분 JSON 흘려봐야 클라이언트가 파싱도 못 하니까 `.stream()` 이 오히려 어색해 보이기도 합니다.
짧고 구조화된 응답은 `.call()`, 길고 자연어 응답은 `.stream()` 정도로 일단 가설을 잡아두고, 양쪽 다 한 번씩 두드려보려고 합니다.

스레드 풀 진짜 마르는 그림도, TTFT 차이도 결국 직접 본 다음에 글을 한 번 더 손볼 수밖에 없을 것 같아요.
