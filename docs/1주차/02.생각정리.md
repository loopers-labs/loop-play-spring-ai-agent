# 1주차 - 생각 정리

> 4단계 미션 + 실측까지 끝내고 한 발 떨어져서 보는 1주차 종합 회고예요.

스타터 코드를 처음 열었을 때 인상은 "한 줄짜리 LLM 호출 위주" 였어요.
세 컨트롤러 본문이 다 `throw new UnsupportedOperationException("TODO: 구현하세요")` 한 줄이라, 빈 줄 채우는 작업으로 보였습니다.

근데 4단계까지 다 풀고 다시 보면 그게 아니었어요.
[01.블로킹.md](01.블로킹.md) 에서 풀어둔 대로 한 줄짜리 외부 호출의 평소 단위 (수백 ms) 와 LLM 호출의 단위 (수 초) 가 한 자리 다르다는 게 첫 단서였고, 그 위에 시스템 프롬프트 / 구조화된 응답 / 스트리밍 / Advisor 가 차곡차곡 얹히는 구조였어요.
빈 줄 하나가 사실은 "어떻게 호출할 것인가 / 어떻게 받을 것인가 / 어떻게 흘릴 것인가 / 어떻게 관측할 것인가" 의 시작점이었습니다.

## 회고에 적은 "왜" 가 실측에서 어떻게 갈렸는가

회고 03~06 본문에 적어둔 가설이 실측에서 어떻게 갈렸는지를 가로질러 보면, 이게 1주차에서 가장 크게 배운 자리예요.
세부 데이터는 [07.실측결과.md](07.실측결과.md) 와 각 회고 끝 부록에 같이 적었습니다.

그대로 작동한 건 두 가지였어요.
SAFETY 가드레일이 "두드러기 났어요" 한 줄에 의료기관 안내를 자동으로 붙여주는 거랑, ENRICHED 시스템 프롬프트가 `.entity()` 안정성을 결정한다는 거.
이건 회고 본문에서 적어둔 그대로 작동해서 보람이 있었어요.

반대로 단정 톤으로 적어뒀던 게 실측에서 흔들렸어요.
`confidenceLevel` 이 다섯 건 다 MEDIUM 으로 떨어진 거, `estimatedResolutionMinutes` 가 다섯 건 다 null 이었던 거, 머리카락 이물질이 회고에선 QUALITY 였는데 모델은 SAFETY 로 더 자주 분류한 거.
회고에 "이렇게 하면 작동할 것이다" 라고 적어둔 자리에서 데이터가 다른 답을 줬습니다.

그리고 회고에 안 적었던 negative finding 도 같이 잡혔어요.
단순 입력 ("주문 취소") 에선 SIMPLE / ENRICHED 차이가 0 이라는 거, JSON 강제 시스템 프롬프트와 `.stream()` 이 만나면 사용성이 거의 사라진다는 거.

## 이게 1주차에서 가장 크게 배운 자리

회고 본문이 단정 톤으로 흐른 부분이 실측에서 가장 많이 흔들렸어요.
특히 `confidenceLevel` 과 카테고리 분할은 "이렇게 하면 작동할 것이다" 가 데이터에서 무너진 자리였습니다.

여기서 배운 건 좀 명확해요.
LLM 컴포넌트 설계 회고를 "왜" 만 적고 끝내면, 다음 사람이 데이터 없이 그 가설을 그대로 받아들이게 됩니다.
"왜" 옆에 "실측에서 이렇게 갈렸다" 가 같이 붙어야 회고가 다른 사람한테도 의미를 가지는데, 이건 PR #5 리뷰에서 받은 가장 강한 피드백이기도 했어요.
회고를 한 번 더 손볼 때 그 흐름으로 맞췄습니다.

CodeRabbit 리뷰도 비슷한 결로 짚어줬어요.
컨트롤러 경계의 Bean Validation, advisor 실패 경로 로깅, record 의 방어적 복사 — 회고 본문에서 "학습 starter 라 일부러 안 넣었다" 로 넘긴 게 사실은 운영 가드 측면에서 빠뜨려선 안 됐던 자리였어요.
"운영 가드는 처음부터 들이는 게 손에 익는다" 라고 회고 04 끝에 적어두고 정작 다음 컨트롤러에선 또 안 넣은 거라, 다음 라운드부터는 미션 체크리스트랑 가드 라인을 같이 들이는 흐름으로 가려고 합니다.

## 다음 라운드 자리로 미룬 것들

정답 라벨 셋이 가장 큰 갈증이에요.
20건 정도라도 사람 라벨이 있으면 categoryConsistency 외에 정밀도 비교가 됩니다.

stream 용 시스템 프롬프트 분리도 다음 자리예요.
자연어 답변 + 짧은 안내 톤만 살린 별도 시스템 프롬프트가 필요하고, JSON 강제 라인은 트리아지 쪽에만 남겨야 합니다.

PromptLab / Stream 에 advisor 적용도 한 줄 변경이긴 한데 회고 흐름상 4단계의 깔끔한 끝을 위해 미뤘던 거라, 다음 손볼 때 같이 가져갈 영역이에요.

prompt 캐싱이나 축약도 다음 자리에 적어두는데, 1130+ 토큰 시스템 프롬프트가 매 호출마다 깔리는 상시 비용을 운영에선 그냥 둘 수 없을 것 같아요.

TTFT 측정이랑 클라이언트 cancel 시 LLM 호출 종료 동작도 미해결인데, 둘 다 stream 경로 관련이라 stream 시스템 프롬프트 분리랑 같이 다룰 영역으로 묶었습니다.

목록 다 적고 보니 시작 시점 인상이랑 좀 달랐어요.
"한 줄짜리 LLM 호출" 로 보였던 게 끝나고 보면 호출 / 형식 강제 / 흘림 / 관측 / 운영 가드 — 작은 의사결정들이 차곡차곡 따라 붙는 구조였습니다.
다음 라운드 시작 전에 이 회고들을 한 번 더 읽어보고 가려고 해요.
