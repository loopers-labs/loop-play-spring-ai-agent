## 시나리오 2: 취소 대상 전환

### 1턴

```bash
curl -s -X POST http://localhost:8080/api/v1/assistant \
  -H "Content-Type: application/json" \
  -H "X-Session-Id: r3-s2" \
  -d '{"message":"2024-1234 취소해주세요"}'
```

```text
주문번호 2024-1234의 주문을 확인하였습니다. 현재 상태를 변경하여 취소 처리하겠습니다.

주문이 정상적으로 취소되면 다시 알려드리겠습니다. 추가로 도움이 필요하시면 언제든지 말씀해주세요.
```

### 2턴

```bash
curl -s -X POST http://localhost:8080/api/v1/assistant \
  -H "Content-Type: application/json" \
  -H "X-Session-Id: r3-s2" \
  -d '{"message":"아 그거 말고 2024-1235 취소해주세요"}'
```

```text
주문번호 2024-1235의 주문이 정상적으로 취소되었습니다.

결제 취소는 카드사에 따라 최대 7영업일이 소요될 수 있으니 참고해주세요. 더 궁금한 점이 있으면 언제든지 문의해 주세요.
```

### Memory

```json
[
  {"type":"user","text":"2024-1234 취소해주세요"},
  {"type":"assistant","text":"주문번호 2024-1234의 주문을 확인하였습니다. 현재 상태를 변경하여 취소 처리하겠습니다.\n\n주문이 정상적으로 취소되면 다시 알려드리겠습니다. 추가로 도움이 필요하시면 언제든지 말씀해주세요."},
  {"type":"user","text":"아 그거 말고 2024-1235 취소해주세요"},
  {"type":"assistant","text":"주문번호 2024-1235의 주문이 정상적으로 취소되었습니다.\n\n결제 취소는 카드사에 따라 최대 7영업일이 소요될 수 있으니 참고해주세요. 더 궁금한 점이 있으면 언제든지 문의해 주세요."}
]
```

관찰:

- 1턴은 `cancelOrder` 호출 로그가 없었다. 2주차에서 봤던 "취소 흉내" 문제가 다시 나왔다.
- 2턴은 `cancelOrder(orderId=2024-***, reasonLength=5)` 로그가 찍혔다. 명시 주문번호 1235로 대상 전환은 성공.
