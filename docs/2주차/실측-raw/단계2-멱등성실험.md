# 단계 2, 멱등성 분기 제거 실험 raw 측정

## 실험 설계

`OrderTools.cancelOrder` 의 멱등성 분기 두 개를 단계적으로 제거하고,
`OrderToolsIdempotencyObservationTest` 의 두 케이스(이미 취소된 주문 재요청 / 정상 주문 연속 취소) 가 어떻게 깨지는지 출력으로 캡처했다.

- 케이스 A, `if (order.status() == CANCELED)` 분기만 제거
- 케이스 B, 위 분기 + `if (!order.isCancelable())` 까지 같이 제거

실험 후 두 분기 모두 원상복구.

## 케이스 A, ALREADY_CANCELED 분기만 제거

`build/test-results/test/...IdempotencyObservationTest.xml` 의 stdout 캡처 (`/tmp/round2-실측/단계2-실험A.txt` 와 동일):

```text
[before] status=CANCELED canceledReason=주소가 잘못 입력되었어요
[cancel re-request] outcome=NOT_CANCELABLE message=조리가 이미 시작되어(CANCELED) 자동 취소가 불가합니다. 상담원 연결이 필요합니다.
[after]  status=CANCELED canceledReason=주소가 잘못 입력되었어요

[1st]     outcome=CANCELED       message=주문이 취소되었습니다. 결제 취소는 카드사에 따라 최대 7영업일이 소요될 수 있습니다.
[between] status=CANCELED canceledReason=집 앞에 사람이 없어요
[2nd]     outcome=NOT_CANCELABLE message=조리가 이미 시작되어(CANCELED) 자동 취소가 불가합니다. 상담원 연결이 필요합니다.
[after]   status=CANCELED canceledReason=집 앞에 사람이 없어요
```

관찰 정리
- 두 번째 호출이 `NOT_CANCELABLE` 분기로 떨어진다. status 가 CANCELED 인데 메시지는 "조리가 이미 시작되어(CANCELED) 자동 취소가 불가합니다", 의미가 깨진 채 사용자에게 전달된다.
- `canceledReason` 은 덮어씌워지지 않는다. 데이터 무결성은 유지됨.
- Outcome 이 NOT_CANCELABLE 이므로 LLM 은 "상담원 연결 필요" 라고 응답할 가능성이 높다. 멱등 분기가 있을 때의 "이미 취소된 상태입니다" 와는 다른 안내가 나간다.

## 케이스 B, ALREADY_CANCELED + NOT_CANCELABLE 둘 다 제거

```text
[before] status=CANCELED canceledReason=주소가 잘못 입력되었어요
[cancel re-request] outcome=CANCELED message=주문이 취소되었습니다. 결제 취소는 카드사에 따라 최대 7영업일이 소요될 수 있습니다.
[after]  status=CANCELED canceledReason=한 번 더 취소

[1st]     outcome=CANCELED message=주문이 취소되었습니다. 결제 취소는 카드사에 따라 최대 7영업일이 소요될 수 있습니다.
[between] status=CANCELED canceledReason=집 앞에 사람이 없어요
[2nd]     outcome=CANCELED message=주문이 취소되었습니다. 결제 취소는 카드사에 따라 최대 7영업일이 소요될 수 있습니다.
[after]   status=CANCELED canceledReason=한 번 더 확인 부탁드려요
```

관찰 정리
- 두 번째 호출도 `order.cancel(...)` 이 그대로 실행되어 `canceledReason` 이 덮어씌워진다.
  - 케이스 1: "주소가 잘못 입력되었어요", "한 번 더 취소"
  - 케이스 2: "집 앞에 사람이 없어요", "한 번 더 확인 부탁드려요"
- 두 번 모두 `Outcome=CANCELED` 메시지가 동일하게 떨어진다. LLM 입장에서는 "취소되었습니다" 가 두 번 나가게 되고, 사용자는 두 번 다 정상 취소된 것처럼 받아들인다.
- `canceledAt` 도 두 번째 호출 시각으로 갱신된다, 원래 취소 시각이 사라지므로 후속 감사/환불 처리에 사용할 timestamp 가 흔들린다.
