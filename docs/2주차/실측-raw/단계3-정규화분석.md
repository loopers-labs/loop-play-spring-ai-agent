# 단계 3 호출 이벤트 정규화 분석

raw 파일 (`단계3-A.txt` / `단계3-B.txt` / `단계3-C.txt`) 의 호출 이벤트를 자동 집계 가능한 단일 포맷으로 정규화한 결과.
raw 는 그대로 보존하며, 본 파일은 분석 / 회귀 회귀 시점의 비교 기준 용도.

스키마: `{call_index, tool_called, tool_name?, arguments?, response_excerpt, source_format, prompt_tokens, completion_tokens}`

`source_format` 은 raw 의 emit 형태가 다양해서 (정상 JSON / `ロン` prefix / `ONGLUGE...` prefix / `.nlm` prefix / 자연어) 호출 정규화 시 토큰 카디널리티 검증에 쓰인다.
`tool_called=true` 는 advisor 로그 `[Tool] getDeliveryStatus` 가 실제로 찍힌 호출, `false` 는 LLM 이 텍스트로 흉내만 낸 호출.

```json
[
  {"call_index": 1, "tool_called": true,  "tool_name": "getDeliveryStatus", "arguments": {"orderId": "2024-1234"}, "response_excerpt": "역삼역 사거리 부근에서 작업 중", "source_format": "natural", "prompt_tokens": 2801, "completion_tokens": 96},
  {"call_index": 2, "tool_called": false, "tool_name": "getDeliveryStatus", "arguments": {"orderId": "2024-1234"}, "response_excerpt": "ロン {\"name\": \"getDeliveryStatus\", \"arguments\": {\"orderId\": \"2024-1234\"}} </tool_call>", "source_format": "leak:ロン_with_close_tag", "prompt_tokens": 1347, "completion_tokens": 29},
  {"call_index": 3, "tool_called": true,  "tool_name": "getDeliveryStatus", "arguments": {"orderId": "2024-1234"}, "response_excerpt": "역삼역 사거리 부근에 있습니다", "source_format": "natural", "prompt_tokens": 2801, "completion_tokens": 89},
  {"call_index": 4, "tool_called": false, "tool_name": "getDeliveryStatus", "arguments": {"orderId": "2024-1234"}, "response_excerpt": "ロン {\"name\": \"getDeliveryStatus\", \"arguments\": {\"orderId\": \"2024-1234\"}} </tool_call>", "source_format": "leak:ロン_with_close_tag", "prompt_tokens": 1347, "completion_tokens": 29},
  {"call_index": 5, "tool_called": true,  "tool_name": "getDeliveryStatus", "arguments": {"orderId": "2024-1234"}, "response_excerpt": "역삼역 사거리 부근에서 작업 중", "source_format": "natural", "prompt_tokens": 2801, "completion_tokens": 79}

```

## 버전 B ("배달 정보 조회" 한 줄)

```json
[
  {"call_index": 1, "tool_called": false, "tool_name": "getDeliveryStatus", "arguments": {"orderId": "2024-1234"}, "response_excerpt": "ONGLUGE {\"name\": \"getDeliveryStatus\", \"arguments\": {\"orderId\": \"2024-1234\"}}", "source_format": "leak:ONGLUGE", "prompt_tokens": 1223, "completion_tokens": 38},
  {"call_index": 2, "tool_called": true,  "tool_name": "getDeliveryStatus", "arguments": {"orderId": "2024-1234"}, "response_excerpt": "역삼역 사거리 부근에서 배송 중", "source_format": "natural", "prompt_tokens": 2538, "completion_tokens": 109},
  {"call_index": 3, "tool_called": false, "tool_name": "getDeliveryStatus", "arguments": {"orderId": "2024-1234"}, "response_excerpt": "ONGL_GET_DELIVERY_STATUS {\"orderId\": \"2024-1234\"}", "source_format": "leak:ONGL_GET_DELIVERY_STATUS", "prompt_tokens": 1223, "completion_tokens": 32},
  {"call_index": 4, "tool_called": true,  "tool_name": "getDeliveryStatus", "arguments": {"orderId": "2024-1234"}, "response_excerpt": "역삼역 사거리 부근에서 배달 중", "source_format": "natural", "prompt_tokens": 2540, "completion_tokens": 111},
  {"call_index": 5, "tool_called": false, "tool_name": "getDeliveryStatus", "arguments": {"orderId": "2024-1234"}, "response_excerpt": "ONGLUGEON{\"name\": \"getDeliveryStatus\", \"arguments\": {\"orderId\": \"2024-1234\"}}", "source_format": "leak:ONGLUGEON", "prompt_tokens": 1223, "completion_tokens": 39}
```

집계: `tool_called=true` 2건 / 5건. `source_format` 카디널리티 4 (natural + 누설 prefix 3종).

누설 prefix 3종이 같은 호출 의도를 다르게 emit 한 결과예요. 자동 집계 파이프라인에서 `source_format`을 prefix 그룹으로 묶거나 `tool_call_intent_detected=true` 같은 상위 플래그로 통합해야 호출률 지표가 흔들리지 않습니다.

## 버전 C ("주문번호 조회용. 메뉴와 결제 금액만 반환한다.")

```json
[
  {"call_index": 1, "tool_called": true,  "tool_name": "getDeliveryStatus", "arguments": {"orderId": "2024-1234"}, "response_excerpt": "역삼역 사거리 부근에서 배송 중", "source_format": "natural", "prompt_tokens": 2564, "completion_tokens": 108},
  {"call_index": 2, "tool_called": false, "tool_name": "getDeliveryStatus", "arguments": {"orderId": "2024-1234"}, "response_excerpt": ".nlm {\"name\": \"getDeliveryStatus\", \"arguments\": {\"orderId\": \"2024-1234\"}} </tool_call>", "source_format": "leak:.nlm_with_close_tag", "prompt_tokens": 1237, "completion_tokens": 29},
  {"call_index": 3, "tool_called": true,  "tool_name": "getDeliveryStatus", "arguments": {"orderId": "2024-1234"}, "response_excerpt": "역삼역 사거리 부근에서 배달 중", "source_format": "natural", "prompt_tokens": 2565, "completion_tokens": 105},
  {"call_index": 4, "tool_called": true,  "tool_name": "getDeliveryStatus", "arguments": {"orderId": "2024-1234"}, "response_excerpt": "현재 배달 상태는 조리 중이며, 라이더는 역삼역 사거리 부근에서 운행 중", "source_format": "natural+weak_confusion", "prompt_tokens": 2582, "completion_tokens": 90},

```

집계: `tool_called=true` 4건 / 5건. `source_format` 카디널리티 3 (natural, leak:.nlm_with_close_tag, natural+weak_confusion).

`call_index=4` 의 응답이 "조리 중이며, 라이더는 ..." 처럼 description 의 거짓 단서("메뉴와 결제 금액만 반환한다") 와 실제 Tool 결과(DELIVERING) 사이의 약한 혼선을 보였어요. 자동 집계 시 이런 케이스를 따로 분류하려고 `natural+weak_confusion` source_format 으로 표기했습니다.

## 호출-응답 페어링 (단계 3-C 의 `.nlm` 케이스 표준화)

raw 의 비표준 마커 (`.nlm`, `ロン`, `ONGLUGE...`) 를 호출 의도로 정규화하면 한 발화당 다음 두 경로 중 하나로 분류 가능합니다.

- `request:tool_call` + `response:tool_result` (Spring AI 가 실제 라우팅한 경우, advisor 로그에 `[Tool]` 찍힘)
- `request:tool_call_intent_leaked` + `response:none` (LLM 이 tool call 토큰을 텍스트로 emit 했지만 라우팅 안 된 경우)

본 분석 파일은 두 경로의 호출률을 `tool_called` boolean 으로 통합 표기했어요. 더 세분화된 페어링이 필요하면 위 두 경로를 별도 필드로 분리하는 게 좋은데, 현재 표본 (각 버전 5회) 으로는 그 분리가 의미가 옅어 통합 표기로 충분하다고 봅니다.

## 회귀 검증 기준 (다음 라운드용)

같은 발화 / 같은 description 으로 재측정할 때 회귀 가드:

1. 각 버전의 `tool_called=true` 카운트가 ±1 이내로 유지되는지
2. `natural` source_format 응답에서 `"역삼역 사거리"` 가 항상 포함되는지 (실제 Tool 결과의 핵심 데이터가 전달되는지)
3. 누설 prefix 카디널리티가 어떻게 변하는지 (qwen2.5 의 emit 안정성 회귀 지표)

이 세 가지를 다음 라운드 PromptLab 류 batch 인프라로 N=20 까지 늘렸을 때도 같은 방향으로 흔들리는지 비교할 예정이에요.
